## B. 认证与密钥（api_key 模式）

- [ ] 未配置 `BOOTSTRAP_TOKEN` 时 `POST /api/auth/bootstrap` 返回 409 `BOOTSTRAP_NOT_CONFIGURED`。
- [ ] 错误 bootstrap_token 返回 401 `BOOTSTRAP_TOKEN_INVALID`；成功后再次 bootstrap 返回 409 `BOOTSTRAP_ALREADY_DONE`。
- [ ] bootstrap 创建的管理员调用 `GET /api/auth/me` 返回 `is_admin=true`。
- [ ] 创建 API Key 返回 `secret`（`dmc_<key_id>_<secret>` 格式）；再次列出密钥不含 secret。
- [ ] 无 `Authorization` 头调用受保护端点返回 401 `AUTH_REQUIRED`。
- [ ] 错误 secret 返回 401 `API_KEY_INVALID`；已吊销密钥返回 401 `API_KEY_REVOKED`。
- [ ] 设置 `expires_in_days` 后用已过期时间的密钥返回 401 `API_KEY_EXPIRED`（可用短过期 + 改库时间验证）。
- [ ] 吊销后再次吊销返回 200（幂等）；吊销他人密钥（非 admin）返回 404 `API_KEY_NOT_FOUND`。
- [ ] `AUTH_MODE=demo` 且 `APP_ENV=production` 拒绝启动；`AUTH_MODE=api_key` 且 `APP_ENV=production` 正常启动（sqlite 时记 WARN）。
- [ ] demo 模式下 `X-Actor` 仍生效且全链路与 V0.9.2 一致。

## C. 项目授权

- [ ] `POST /api/projects/{id}/members` 添加 viewer/editor/owner 成功并记录事件与审计。
- [ ] viewer 调用任一设计写端点（如 `PUT /api/models/{id}`）返回 403 `PROJECT_ROLE_INSUFFICIENT`。
- [ ] viewer 可正常调用全部 GET 与 `POST /api/models/{id}/ddl`（只读生成）。
- [ ] editor 可写设计对象、可走生命周期、可导入血缘；调用成员管理返回 403。
- [ ] owner 可添加/移除/改角色成员。
- [ ] 非成员访问项目资源返回 403 `PROJECT_ACCESS_DENIED`；项目不存在仍返回 404 `PROJECT_NOT_FOUND`。
- [ ] admin 账号可访问全部项目。
- [ ] 移除最后一个 owner 返回 409 `MEMBER_LAST_OWNER`。
- [ ] 指定不存在的 user_key 返回 404 `USER_NOT_FOUND`；禁用用户返回 409 `USER_DISABLED`。
- [ ] 认证失败/授权拒绝在审计日志可见（`auth.denied`）并计入 `modeling_auth_denied_total`。

## D. dbt manifest 连接器

- [ ] 用 fixture manifest（≥3 个 model 节点 + ≥2 个 source + parent_map）导入，边数、source_ref、scope_key、`lineage_type=dbt_dependency` 符合合同。
- [ ] 相同 manifest 相同 run_id 重放返回 200 `replayed=true`，边数量不翻倍。
- [ ] 修改 manifest 内容后使用相同 run_id 返回 409 `LINEAGE_RUN_ID_REUSED`。
- [ ] manifest 引用平台不存在的 model_key：默认返回 422 `DBT_NODES_UNMATCHED` 且 `details.unmatched_sample` 给出样例。
- [ ] `skip_unmatched=true` 时导入成功，响应 `connector.skipped_unmatched` 计数正确。
- [ ] manifest 缺 `metadata`/`nodes`/`sources`/`parent_map` 返回 422 `DBT_MANIFEST_INVALID`。
- [ ] 推导边数超过 1000（或体积超限）返回 422 `DBT_MANIFEST_TOO_LARGE`。
- [ ] 导入后 `lineage` 图谱视图可见外部边，`lineage/health` 出现对应 `source_system=dbt` 分组。
- [ ] viewer/非成员调用导入端点返回 403。
- [ ] 导入批次记录可在 `lineage/import-runs` 查询，`result_json.connector` 含连接器元数据。

## E. 发布评审上下文

- [ ] 对草稿模型调用 `GET /api/models/{id}/review-context`，`validation`/`change_summary`/`impact`/`graph_diff`/`lineage_coverage` 五个区块齐全。
- [ ] 无发布基线的模型返回 `analysis_mode=no_published_baseline`。
- [ ] 项目快照不足两次时 `graph_diff.available=false` 且给出原因。
- [ ] 建立一条无外部边佐证的设计关系后，该边出现在 `lineage_coverage.uncovered`。
- [ ] `impact` 与 `GET /api/models/{id}/impact` 结果一致（候选集合相同）。
- [ ] `POST /api/models/{id}/submit-review` 响应含 `review_context` 摘要；运行事件 `review.submitted` 的 detail 含同名字段。
- [ ] 有阻断校验错误时 submit-review 仍返回 422 `MODEL_VALIDATION_FAILED`（行为不变）。

## F. full_snapshot 停用确认

- [ ] 停用比例低于阈值（如 1/4）的 full_snapshot 无需确认即成功。
- [ ] 停用比例高于阈值（如 3/4）且未带 `confirm_deactivation` 返回 422 `LINEAGE_DEACTIVATION_CONFIRM_REQUIRED`，details 含 planned/active/ratio/threshold。
- [ ] 同上场景带 `confirm_deactivation=true` 成功，且 `lineage_import_runs.deactivation_confirmed=true`。
- [ ] 空 full_snapshot（停用本 scope 全部 active 边）无确认返回 422。
- [ ] `POST /api/projects/{id}/lineage/preview` 返回 `planned_deactivate_ratio` 与 `confirmation_required`。
- [ ] incremental 导入不受确认门槛影响（回归 V0.9.2 行为）。
- [ ] 修改 `FULL_SNAPSHOT_DEACTIVATE_RATIO_THRESHOLD` 配置后阈值行为随之变化。
