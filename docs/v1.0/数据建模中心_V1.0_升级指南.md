# V0.9.2 → V1.0 升级指南

## 1. 适用范围

适用于已运行 V0.9.2、数据库 Alembic revision 为 `b5f2c4a9d703`（head）的参考工程。V1.0 是**破坏性版本**：引入认证与项目级授权（API Key 替换 `X-Actor` 演示身份）、放开生产启动门禁（`AUTH_MODE=api_key`）、改变 full_snapshot 大比例停用行为（新增人工确认门槛）。请完整阅读第 3、5 节后再执行。

**版本路径提醒**：如果当前 revision 不是 `b5f2c4a9d703`（例如停在 `a4d7c92f5e10` 或更早），必须先按历史升级文档（`docs/v0.9/数据建模中心_V0.9.2_升级指南.md` 及其引用链）升级到 V0.9.2，再执行本指南；不要跳过中间 revision。

## 2. 升级前检查

1. 停止应用服务。
2. 备份数据库（`data/platform.db` 或 PostgreSQL 库）、代码与环境变量（`.env`）；推荐在数据库副本完整演练。
3. 检查迁移状态：

   ```bash
   python -m alembic current
   python -m alembic heads
   ```

   预期当前 revision 为 `b5f2c4a9d703`，且只有一个 head。若版本不同、存在多个 head 或本地模型有未提交自定义，不应直接继续。
4. **导出成员与密钥台账**（如已存在任何外部签发的凭据/成员约定）：V1.0 回滚会删除 `users`/`api_keys`/`project_members`，密钥哈希不可恢复（见第 6 节）。
5. 阅读 `docs/v1.0/数据建模中心_V1.0_需求说明书.md` 第 3 章（身份与授权模型）与第 8.3 节（兼容性矩阵），确认接入方（连接器、CI、前端）已按第 5 节适配。
6. 确定运行模式：
   - 本地/开发/测试：保持 `AUTH_MODE=demo`（默认），行为与 V0.9.2 一致；
   - 生产/预发：设置 `AUTH_MODE=api_key`，并预先配置 `BOOTSTRAP_TOKEN`（引导完成后立即吊销引导密钥）。

## 5. 升级后必做操作与行为变更

### 5.1 api_key 模式引导（生产必做）

```bash
# 1. 配置环境变量
export APP_ENV=production
export AUTH_MODE=api_key
export BOOTSTRAP_TOKEN=<高熵随机值>
export DATABASE_URL=postgresql+psycopg://...

# 2. 启动后执行一次性引导（创建首个管理员，secret 仅返回一次）
curl -X POST http://127.0.0.1:8000/api/auth/bootstrap \
  -H 'Content-Type: application/json' \
  -d '{"bootstrap_token":"...","user_key":"u:admin","display_name":"平台管理员"}'

# 3. 用返回的 Bearer 令牌创建连接器服务账号密钥、登记项目成员
# 4. 吊销引导密钥：POST /api/auth/api-keys/{key_id}/revoke
```

### 5.2 行为变更清单（接入方必读）

| # | 变更 | V0.9.2 | V1.0 | 接入方动作 |
| --- | --- | --- | --- | --- |
| 1 | 认证 | `X-Actor` 演示头 | api_key 模式必须 `Authorization: Bearer dmc_<key_id>_<secret>`；`X-Actor` 忽略 | 所有客户端/连接器/CI 申请并配置密钥 |
| 2 | 生产启动 | 一律拒绝 | `AUTH_MODE=api_key` 时放行（demo+production 仍拒绝） | 运维按模式配置 |
| 3 | full_snapshot 停用 | 直接停用 | 计划停用比例 > 阈值（默认 0.5）需 `confirm_deactivation=true`，否则 422 `LINEAGE_DEACTIVATION_CONFIRM_REQUIRED` | 连接器改为 preview → 确认 → 提交两步式 |
| 4 | lineage preview 响应 | 既有字段 | 新增 `planned_deactivate_ratio`、`confirmation_required` | 读取新字段决定是否确认 |
| 5 | submit-review 响应/事件 | 既有字段 | 新增 `review_context` 摘要 | 前端展示（可选，旧客户端可忽略） |
| 6 | `/metrics`、`/api/observability/summary` | 既有字段 | 新增 `modeling_*` 指标族与 `auth`/`lineage` 摘要 | 监控配置更新 |
| 7 | lineage health | 内存全量汇总 | SQL 聚合，响应形状不变 | 无 |

### 5.3 演示数据

demo 模式首次启动会幂等插入演示管理员 `u:demo.admin`（admin）与各既有项目的 owner 成员记录；不影响既有业务种子数据。

## 6. 回滚

```bash
python -m alembic downgrade b5f2c4a9d703
```

- 回滚删除 `users`/`api_keys`/`project_members` 三张表并移除 `lineage_import_runs.deactivation_confirmed` 列（SQLite batch 模式重建表）。
- **回滚前必须导出成员与密钥台账**：回滚后全部 API Key 失效且不可恢复（服务端只存哈希），需向持有方重新签发；生产环境回滚须变更评审。
- V0.9.2 应用代码可以读回滚后的库（不认新端点）；但请勿"只回滚代码保留新库"或"只回滚库保留新代码"——两者必须同步。
- 与 V0.9.2 降级保护同风格：不得使用 `alembic stamp` 绕过迁移；不得为让降级成功而删除数据。
- 既有业务表、血缘数据、图谱快照不受回滚影响。
