## 一、产品定位

- **平台愿景**：通用型数据开发管理平台，纵向先做「数据建模中心」，跑通后再横向扩展 ETL 开发、数据质量监控、血缘图谱等条线。
- **建模中心定位**：以**业务需求为入口**，以**正式模型版本为交付物**；统一逻辑模型描述业务结构，通过引擎适配层承接 PostgreSQL / MySQL / Hive 的物理差异。
- **建设策略**：轻量可运行 MVP，模块化单体，按模块演进；不为第一阶段引入微服务、消息队列、图数据库。

## 三、核心业务闭环

```
业务需求登记 → 调研补充 → 建立模型草稿 → 设计表/字段/关系
      → 规则校验（错误阻断 / 警告提示）
      → 提交评审（冻结快照 + 生成评审上下文）
      → 退回整改（新修订）↔ 评审通过
      → 正式发布（同一事务：版本快照 + 模型状态 + 活动事件 + 审计）
      → DDL 预览 / 数据字典交付
      → 变更时：start-change 发起新草稿 → 再次走校验/评审/发布 → V2
```

**模型状态机**（服务端强制）：

| 当前状态 | 允许动作 | 目标状态 | 关键约束 |
|---|---|---|---|
| draft | 编辑、校验、提交评审 | draft / in_review | expected_revision 乐观锁；提交前阻断校验必须通过 |
| in_review | 通过 / 退回 | approved / draft | 退回必须记录意见 |
| approved | 发布 | published | 事务内写快照+事件+审计 |
| published | 发起变更 | draft | 保留 published_version_no 与历史快照 |

## 四、技术架构（按文档 V0.6 参考实现）

- **后端**：Python + FastAPI + Pydantic + SQLAlchemy 2.x + Alembic（模块化单体：路由 / 领域规则 / ORM / DDL 适配 / 可观测分层）
- **数据库**：SQLite 默认（`data/platform.db`，开发演示）；PostgreSQL 为生产目标，迁移用 Alembic 管理
- **前端**：静态 HTML/CSS/JS 工作台（无构建步骤，保持开发效率；Vue 3 + TS 为正式产品目标，不被原型锁定）
- **部署**：本机 `uvicorn` 一键启动；Docker Compose 可选
- **可观测**：X-Request-ID 贯穿（响应头 + 错误体 + 日志 + 事件 + 审计）、JSON 结构化日志、`/api/health/live`（不依赖 DB）与 `/api/health/ready`（检查 DB + migration revision）、`/metrics` 简化指标、`activity_events` 业务时间线、`audit_logs` 安全审计
- **安全默认**：不执行目标 DDL；`APP_ENV=production/staging` 拒绝启动；`X-Actor` 仅本地演示身份

## 六、API 契约总览（26 端点，前缀 `/api`）

- **健康**：`/api/health`、`/api/health/live`、`/api/health/ready`
- **项目**：`GET/POST /api/projects`
- **主题域**：`GET/POST /api/projects/{id}/subject-areas`
- **需求**：`GET/POST /api/projects/{id}/requirements`、`GET/PUT /api/requirements/{id}`、`GET /api/requirements/{id}/models`、`POST/DELETE /api/requirements/{rid}/models/{mid}`
- **模型**：`GET/POST /api/projects/{id}/models`、`GET/PUT /api/models/{id}`（expected_revision 乐观锁）
- **生命周期**：`POST /api/models/{id}/validate`、`/submit-review`、`/approve`、`/reject`、`/publish`、`/start-change`
- **关系**：`GET/POST /api/models/{id}/relationships`、`DELETE .../{rid}`
- **版本**：`GET /api/models/{id}/versions`、`GET /api/models/{id}/versions/diff?from_version=&to_version=`
- **交付**：`POST /api/models/{id}/ddl`（target_engine: postgresql/mysql/hive）
- **观测**：`GET /api/projects/{id}/events`、`GET /api/dashboard/{id}`、`GET /api/observability/summary`、`GET /metrics`

错误体统一：`{error:{code,message,details},request_id}`；关键错误码：REVISION_CONFLICT(409)、INVALID_STATE(409)、MODEL_VALIDATION_FAILED(422)、CROSS_PROJECT_RELATIONSHIP、SELF_RELATIONSHIP、RELATIONSHIP_FIELD_NOT_FOUND、NO_PUBLISHED_BASELINE 等。

## 七、关键业务规则

1. **乐观并发**：草稿保存必须携带 `expected_revision`，不匹配返回 409，不静默覆盖。
2. **校验规则**（错误阻断 / 警告分级）：NAM-001 表名标识符合法、NAM-002 字段名 snake_case、NAM-003 表内字段名不重复、MOD-001 模型编码项目内唯一、COL-001 逻辑类型有效且有映射、COL-002 DECIMAL 精度/小数位合法、COL-003 字段描述缺失（警告）、KEY-001 主键存在且不可空、SRC-001 来源缺失（提示）、SEC-001 敏感级标记（警告）。
3. **发布事务**：状态+快照+活动事件+审计同一事务提交，失败整体回滚，不留半发布状态。
4. **版本语义**：edit_revision（草稿修订，乐观锁）与 published_version_no（正式版本号）分离；发布快照不可变；字段 diff 以 field_code 为匹配键。
5. **关系校验**：两端同项目、禁止自引用、字段必须存在且成对、类型组合唯一。
6. **DDL 安全**：标识符白名单校验、默认值白名单、逻辑类型按引擎映射表转换、`execute_on_target=false`。

## 八、已知限制（文档明示，搭建时保留）

- 无真实认证与资源级 RBAC（X-Actor 仅演示）；production 启动阻断必须保留。
- 需求状态允许通用 PUT，无严格状态机守卫。
- 模型关系不进版本快照，diff 不含关系变化。
- DDL 为字符串预览，未对真实引擎执行验证。
- 字段粘贴为固定列序 TSV（编码/中文名/类型/主键/可空/说明）。
- 前端为静态页面，无浏览器 E2E 门禁。
